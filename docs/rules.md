# Rules and what enforces them

Each rule names the check that fails when someone breaks it. `bash scripts/mutants.sh` reapplies each recorded past mistake to a scratch copy and fails if the tests miss one. When the operator corrects you, add a row here (see `AGENTS.md`).

| Rule | Enforced by |
| --- | --- |
| Saved ids and stored formats never change: entry ids, `WindowAction` raw values, shortcut and placement JSON | `SavedDataTests`, the stored-format fixtures in `LauncherPlacementTests`, mutants M1, M2, M3 and M5 |
| Shortcuts bind under their shipped keys, and a shortcut is saved only after it registers. The one exception: turning on Speech to text saves Right ⌘ for dictation while it waits for access, unless another shortcut has it | `SavedDataTests.aShortcutSavedUnderAShippedKeyFiresItsCommand`, `HotKeysTests`, mutants M12, M13 and M28 |
| A dictation press before the model is ready says why, with the live percent while it downloads, even when Ciel is in the background | `DictationTests.aPressBeforeTheModelIsReadySaysWhy`, the background dictation step of the window check, mutant M27 |
| Unset toggles read as on, under their shipped keys, through `Preferences` | `SavedDataTests.togglesAreOnUntilTurnedOffUnderTheirShippedKeys`, mutant M15 |
| A new `WindowAction` case defines its geometry | The compiler: `unitRect` switches over every case with no `default`. Mutant M4 |
| The bundle id lives only in `AppIdentity` and `Resources/Info.plist` | `SavedDataTests.bundleIdentifierMatchesInfoPlist`, mutant M8 |
| Native checks run only under the checks bundle id, and an unknown flag never launches the app | `LaunchMode` and `LaunchModeTests`, the identity step in `check.sh` (exit 64), mutants M9 and M10 |
| A handler that an Apple API calls off the main thread is `@Sendable`, never main-actor isolated, and hops to the main actor inside, so it never traps on entry. Every such call lives in `Sources/Ciel/App/OffMainCallbacks.swift` | The compiler: each wrapper in `OffMainCallbacks.swift` takes an `@escaping @Sendable` handler, so a main actor closure does not compile. `scripts/lint/lint-callbacks.sh` in `check-fast.sh` fails on a listed API name outside that file, with its self-test `scripts/lint/check-lint-callbacks.sh`. The missing app launch step of `--ui-test` (`LauncherCheck`), which runs the app's real `openApplication` handler |
| Quitting frees the transcribe.cpp session first: `applicationShouldTerminate` waits for `TranscribeCppTranscriber.close()`, since exit with an open session aborts in ggml's static destructors | `--speech-quit-test`, which `check.sh` runs when `CIEL_SPEECH_MODEL` names a model and the check job always sets it |
| Window commands never target Ciel's own windows | `ForeignProcess` in `WindowController.swift`, `WindowOperationTests.ownProcessIsNeverATarget`, mutant M14 |
| A window command on a full screen window first takes it out of full screen, waits up to 1.5 s for the flag to clear and the frame to hold, then applies on the screen it lands on | `WindowOperationTests.leavesFullScreenFirst` and `fullScreenExitState`, mutant M29 |
| Window settle retries an unchanged window after 0.2 s, matches within 3 pt, settles as constrained only when the retry repeats, and never yields before the window responds | `FrameSettleTests`, `WindowOperationTests`, mutants M16 to M20 |
| An invalidated icon load never delivers and never holds a load slot | `IconCacheTests`, whose waits fail after 3000 polls of 1 ms instead of hanging, mutants M21 and M22 |
| A test wait spends its budget only on its own polls, so time it spends queued behind other suites' main actor work never times it out | `WaitUntilTests`, mutant M34 |
| Onboarding and Settings save a launcher shortcut only after Spotlight lets it go, through the shared `SpotlightGuide`, and read a Spotlight shortcut missing from the saved list as on | `OnboardingTests`, `SettingsSpotlightTests`, the onboarding and Settings Spotlight steps in `SmokeCheck`, mutants M24, M25 and M26 |
| A launcher shortcut that Spotlight holds opens System Settings at Keyboard Shortcuts > Spotlight, and the guide card stays under System Settings until Spotlight lets go or the user cancels | `SettingsSpotlightTests`, `OnboardingTests`, the Spotlight guide step of the window check, mutants M31 and M32 |
| A speech model counts as ready only after its size and SHA-256 match the pinned values | `SpeechModelStoreTests`, mutant M23 |
| Ad-hoc builds sign without hardened runtime. Developer ID builds sign app and framework with hardened runtime, one Team ID and library validation on | The signature check at the end of `scripts/build.sh`, and the launch step in `.github/workflows/checks.yml` |
| `scripts/release/appcast.sh` writes an appcast only for a signature that matches `SUPublicEDKey`, and `sign_update` output never reaches a log or a `bash -x` trace | The wrong-key and `bash -x` malformed key cases in `scripts/release/check-appcast.sh` |
| The disk image holds the signed app unchanged, an Applications link and the window layout, and nothing else | The checks in `scripts/release/dmg.sh`, which `checks.yml` runs on each pull request and each push to main |
| A failed command in `scripts/release/dmg.sh` prints its line, the command and its exit status | `scripts/release/check-dmg.sh` in `check-fast.sh` |
| Catalog events match canonical roots, so symlinked folders still update | `CatalogTests`, mutant M11 |
| A result picked for a query ranks first, after exact title matches, whenever the typed query is the start of that query: a pick under `first t` ranks for `f` and `fir` | `LearnedRankingTests.aPickRanksFirstForEveryStartOfTheQueryItWasPickedFor` and `anExactTitleOutranksALearnedEntry`, `UsageHistoryTests.storedPicksReadBackAndMalformedRowsAreSkipped`, mutant M33 |
| Tab cycles categories in order, and a window command reports its own title | `LauncherCategoryTests`, `WindowOperationTests`, mutants M6 and M7 |
| Result row icons draw in the colors `ResultCell.mark` sets, selected or not. AppKit's selected-row style never recolors them, and the hover overlay never covers a selected row | `LauncherCellTests.resultIconsDrawInTheirRowColorsSelectedOrNot` and `aHoveredRowSelectedFromTheKeyboardKeepsItsSelectionFill`, mutant M30 |
| Shell syntax checks run only through `scripts/lint/check-syntax.sh`, which runs `bash -n` once per file, because `bash -n` checks only its first file | `scripts/lint/lint-shell.sh` in `check-fast.sh` fails on any other `bash -n`, `sh -n` or `-o noexec` call in a tracked script, hook or workflow, and `scripts/lint/check-lint-shell.sh` proves both |
| When a source line under a public claim changes (network use, build architecture, full screen handling, moving windows between Spaces, dictated audio), every claim listed for that fact in `scripts/lint/claims.txt` is read again | `scripts/lint/lint-claims.sh` in `check-fast.sh`, and `scripts/lint/check-lint-claims.sh` |
| Colors, labels, switches and the About panel come from `Sources/Ciel/App/DesignSystem.swift` | `scripts/lint/lint-colors.sh` in `check.sh`. Its error names the token to use |
| Swift code carries no new comments. Say it with a name, a type or a test. A fact about code we cannot change goes on a `// WARNING:` line, which the lint does not count, and the comment count per file only shrinks | `scripts/lint/lint-comments.sh` in `check-fast.sh`, against `scripts/lint/comment-baseline.txt` and its copy at the base commit: `CIEL_COMMENT_BASE`, which CI sets to the pull request base sha or, for a push to main, the previous main, else the merge base with `origin/main`. Its errors name the fix |
| Native behavior works in the real app, not only in fakes | The native modes in `check.sh`, which CI runs on macOS with the window check required |
| Concurrency is checked, never silenced | Swift 6 language mode in `Package.swift`, and `check.sh` builds with warnings as errors |
| A mutant follows the code it targets when you move or change that code | `mutants.sh` fails with `<id> no longer applies to <file>`, in its own CI job |
| `AGENTS.md` stays under 4096 bytes and `CLAUDE.md` links to it. Each tracked Markdown file is on the docs list and under its line cap. No file has an em dash | `scripts/lint/check-docs.mjs` in `check-fast.sh`, and `scripts/lint/check-lint-docs.sh` |
| Shell, JavaScript, workflow and hook files carry no comments, except a `WARNING:` line about a tool this repo cannot change | `scripts/lint/check-comments.mjs` in `check-fast.sh`, and `scripts/lint/check-lint-script-comments.sh` |
| The comment baseline follows a moved Swift file, so a move keeps its count and a move with a new comment fails | `scripts/lint/lint-comments.sh`, and the move cases in `scripts/lint/check-lint-comments.sh` |
| Swift code has no `as!`, except up to 4 CoreFoundation casts in `WindowAccessibility.swift` | `scripts/lint/lint-casts.sh` in `check-fast.sh`, and `scripts/lint/check-lint-casts.sh` |
| Each `scripts/` path in a workflow, hook, script, skill or doc names a tracked file | `scripts/lint/lint-paths.sh` in `check-fast.sh`, and `scripts/lint/check-lint-paths.sh` |
| Commits carry no trailers and no Co-authored-by lines. Dependabot may sign off its own commits | `scripts/lint/check-commits.sh` in the pre-push hook and on the pull request commits in CI, and `scripts/lint/check-lint-commits.sh` |
| Commits carry no secrets | gitleaks on the staged changes in `.githooks/pre-commit`, on the pushed commits in the pre-push hook, and on the new commits of each pull request and push to main in CI |
| Dependencies carry no high or critical advisory (CVSS 7.0 or more) | `scripts/lint/audit.sh` (osv-scanner on `Package.resolved`, `site/bun.lock` and the dmgbuild requirements) in the `check` job of `checks.yml`, and `scripts/lint/check-lint-audit.sh` |
| A window or utility command with no verify recipe is listed in `VerifyRecipeTests`, and leaves the list when it gains one | `VerifyRecipeTests` |
| Swift code holds no declaration that nothing uses. A property that only keeps a `Cleanup` or a dispatch source alive, and a `Codable` field, count as used | `scripts/lint/dead-code.sh` (periphery, settings in `.periphery.yml`) in the `dead-code` job of `checks.yml` |
| The TypeScript and JavaScript (the site, `scripts/lint` and the verify skill scripts) pass strict type checks and the type-aware oxlint rules. The type error count per file only shrinks | `node_modules/.bin/oxlint` and `scripts/lint/check-types.mjs` in `check-fast.sh`, against `scripts/lint/type-baseline.txt` and its copy at the merge base with `origin/main`, and `scripts/lint/check-lint-types.sh` |
| A closed PR leaves no preview and no head branch behind (rule in mauricio-taste `config/AGENTS.md`, "Previews and branches") | `.github/workflows/preview-teardown.yml` runs `scripts/preview-teardown.sh` on each close, and `.github/workflows/preview-sweep.yml` catches a close that started no run |
